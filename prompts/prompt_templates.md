# Prompt Templates

This directory documents the prompt surface used by the experiment. Full raw
provider request/response logs are not released. The released prompt artifacts
are deterministic, model-facing inputs or prompt templates.

## Upstream Summary Prompt

The upstream prompt jobs are released as JSONL files under
`prompts/upstream_prompt_jobs/`.

Each row has:

- `event_id`
- `treatment`
- `representation_seed`
- `generator_seed`
- `evidence_bank_path`
- `prompt`
- for T3 rows, `profile_id`

The main T2/T3 prompt jobs used neutral analyst framing:

```text
You are rendering a source-grounded financial event representation.
Treatment: {treatment}
Representation seed: {representation_seed}

Rules:
- Use only the supplied canonical evidence-unit bank.
- Use source IDs for every factual claim.
- Cite only source IDs in the form S### or X###.
- Never cite evidence IDs such as E_SRC_###, E_XBRL_###, or E_CTX_###.
- Company, ticker, and event date may be mentioned only when supplied below.
- Do not mention post-event outcomes, realized market reactions, hidden labels, future filings/news, or unsupported external facts.
- Do not provide a buy/hold/sell recommendation.
- Do not infer unsupported facts.
- Keep the output in a neutral analyst-style summary of roughly 350-500 tokens.

Event metadata:
{event_metadata}

Canonical evidence-unit bank:
{canonical_evidence_units}
```

The T2*/T3* robustness prompt jobs remove the neutral-analyst framing while
keeping the same evidence-bank input, source-citation rules, treatment axis,
and output length target:

```text
You are rendering a source-grounded financial event representation.
Treatment: {treatment}
Representation seed: {representation_seed}

Rules:
- Use only the supplied canonical evidence-unit bank.
- Use source IDs for every factual claim.
- Cite only source IDs in the form S### or X###.
- Never cite evidence IDs such as E_SRC_###, E_XBRL_###, or E_CTX_###.
- Company, ticker, and event date may be mentioned only when supplied below.
- Do not mention post-event outcomes, realized market reactions, hidden labels, future filings/news, or unsupported external facts.
- Do not provide a buy/hold/sell recommendation.
- Do not infer unsupported facts.
- Keep the output roughly 350-500 tokens.

Event metadata:
{event_metadata}

Canonical evidence-unit bank:
{canonical_evidence_units}
```

## Downstream Decision Prompt

Downstream prompts are generated by `code/scripts/build_downstream_requests.py`
from rendered treatment packets and the profile definitions in
`code/scripts/experiment_run_profiles.py`.

The static instruction block is:

```text
You are a downstream decision agent in a controlled experiment.

Task:
- Read the supplied treatment packet.
- Then apply the supplied investor profile and decision seed.
- Estimate expected_return_5d as a decimal return in [-0.20, 0.20].
- Provide confidence in [0, 1].
- Choose one action from buy, hold, sell.
- Provide action_strength in [-1, 1].
- Provide 2 to 5 concise key_reasons.
- Cite evidence_used as source IDs from the packet when available.
- Provide optional uncertainty_notes.
- Use only information present in the treatment packet, including company, ticker, and date if supplied.
- Do not use external knowledge, browsing, post-event outcomes, realized market reactions, hidden labels, future filings/news, or unsupported facts.

Return JSON with keys:
event_id, treatment, upstream_model_family, profile, profile_group, model_family,
representation_seed, decision_seed, expected_return_5d, confidence, action,
action_strength, key_reasons, evidence_used, uncertainty_notes.
```

Each downstream request appends:

```text
Treatment packet:
{rendered_treatment_text}

Investor profile:
Profile: {profile}
Group: {profile_group}
Horizon: {horizon}
Focus: {focus_items}
Style: {style}

Decision seed: {decision_seed}

Return only valid JSON.
```

## Released Prompt-Job Files

See `prompts/prompt_manifest.csv` for row counts, file sizes, and checksums.

The complete downstream request JSONL files are not released because they are
large operational bundles with substantial duplicated treatment text. They can
be regenerated from the released code and model-facing inputs; the
analysis-level decision traces under `results/traces/` provide the validated
post-response rows used for metric computation.
